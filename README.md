# うたジャッジ — ブラウザ採点カラオケ

音程だけでなく、**こぶし・しゃくり・ビブラート・フォール**まで判定して点数を出すカラオケです。
インストール不要で、ブラウザ（スマホでも可）から遊べます。

🎤 遊ぶ：GitHub Pages のURL（リポジトリの Settings → Pages で確認）

## 遊び方
1. 曲を選ぶ（カウントダウン → 伴奏スタート）
2. マイクに向かって歌う（**イヤホン推奨**。スピーカーだと伴奏がマイクに入ります）
3. 結果画面で、音程・リズム・表現（こぶし／しゃくり／ビブラート／フォール）の内訳を確認

## 採点の仕組み
| 項目 | 配点 | 内容 |
|---|---|---|
| 音程 | 55 | お手本の音ごとに、歌った音の高さを判定（±0.5半音まで満点、1.5半音で0点。オクターブ違いは許容） |
| リズム | 15 | 音の出だしのタイミング（歌い手の遅れ・マイクの遅延は自動で補正） |
| 表現 | 30 | こぶし・しゃくり・フォールはお手本にある箇所で判定。ビブラートは0.6秒以上伸ばした音すべてで判定 |

- 表現の判定が無い曲では、その分は音程・リズムで点数が決まります。
- ランク：S ≥95 / A ≥85 / B ≥70 / C ≥50 / D

## 曲の追加方法（誰でもできます）

1. `songs/` の中に曲IDのフォルダを作る（例：`songs/my-song-01/`）
2. 次のファイルを入れる
   - `source.wav`（または mp3 / m4a / flac / ogg）… **お手本の旋律を解析する原曲**
   - `backing.wav`（同上）… **カラオケで流す伴奏（歌なし）**。無ければ原曲を流します
3. `meta.json` を作る（任意。無くても自動で雛形ができます）
   ```json
   {
     "title": "曲名",
     "artist": "作者名",
     "lyrics": [
       { "t": 0.86, "text": "1行目の歌詞" },
       { "t": 5.98, "text": "2行目の歌詞" }
     ]
   }
   ```
   `t` は秒。歌詞の表示タイミングです。
4. GitHubにpushする → Actions が `ref.json`（お手本データ）と `audio.mp3` を自動生成してコミットし、サイトに曲が追加されます。

手元で作る場合：
```bash
pip install -r tools/requirements.txt
python tools/build_song.py            # 新しい曲だけ処理
python tools/build_song.py --force    # 全部作り直す
```

## お手本データについて
- 原曲（ドラム・ベース・和音が入ったミックス）から、リード旋律を自動推定しています。
- 完全ではないので、ミスの多い曲は `source.wav` をボーカル（旋律だけ）の音源に差し替えると精度が上がります。
- `ref.json` は10ms刻みのMIDIノート番号（無声は `null`）です。手作業で直す場合は、この配列を編集しても構いません。

## 構成
```
index.html          画面
css/style.css       デザイン
js/pitch.js         マイクからのピッチ検出（YIN法）
js/analysis.js      音の区切り・こぶし/しゃくり/ビブラート/フォールの検出
js/scoring.js       採点
js/app.js           画面の動き・マイク・描画
songs/index.json    曲一覧（自動生成）
songs/<曲ID>/       source / backing / meta.json / ref.json / audio.mp3
tools/build_song.py お手本データの生成
```

## 既知の制限
- 採点はブラウザ上で行うため、マイクの品質・環境（スピーカーの音の回り込み、ノイズ）で点数が変わります。
- ビブラート・こぶし等の判定は「波形の形」からの推定で、人間の採点とは完全には一致しません。
